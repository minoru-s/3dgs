# 処理時間の軽量化メソッド（M2 / T4実測ベース）

Apple M2/16GBのローカル実測と、Colab T4でFHD約40秒の動画を処理した実測をもとにした指針です。

## 実測: ボトルネックは環境で違う

### Mac（旧standard、180/180枚登録、30,000 step）

| ステージ | 実測時間 |
|---|---:|
| フレーム抽出 | 約54秒 |
| COLMAP SfM | 約3.2分 |
| Brush学習 | 107.5分 |

Macでは学習が96%以上を占めたため、解像度・反復数・Gaussian上限を下げるのが主に効きます。

### Colab T4（旧設定、200抽出→180使用→99登録）

| ステージ | 実測時間 |
|---|---:|
| セットアップ | 2.7分 |
| 抽出 | 0.9分 |
| 特徴抽出 | 7.6分 |
| 特徴照合 | 17.7分 |
| Mapper | 15.5分 |
| gsplat学習 | 41.6分 |
| **合計** | **86.0分** |

旧Colab版は特徴抽出・照合を明示的にCPUへ固定しており、SfMだけで約41分かかっていました。Colabでは「学習だけがボトルネック」ではありません。

## 実装した軽量プロファイル

1. **有効キーフレーム選別**: 目標枚数の2倍を候補抽出し、時間区間ごとにシャープネス70% + 画面/特徴点変化30%で選択。200枚一律処理を標準120枚へ削減。
2. **解像度**: 標準1600pxから1280pxへ。学習の画素処理量は約36%減。
3. **SfM GPU化（Colab）**: `pycolmap-cuda12==4.1.1`でSIFT抽出・照合をCUDA実行。
4. **Global Mapper**: 高速なGlobal Mapperを先行し、登録率50%未満だけIncremental Mapperへ退避。
5. **軽量学習**: Colabは8,000 step・60万Gaussian・SH degree 2、Macは10,000 step・60万Gaussianへ変更。
6. **不要な評価を停止（Colab）**: 評価レンダリングと頻繁なTensorBoard書込みを止める。
7. **段階保存**: 選別画像、SfM、学習中間PLY、最終PLYをDriveへ保存・検証。

## 高品質のまま30分を狙うFastGS経路

`fast_quality` は上の軽量プロファイルとは別系統です。入力解像度や表現力を削らず、180枚・長辺1600px・SH3・30,000 iterationを維持します。

1. **多視点整合densification**: 単一画像の勾配だけでGaussianを増やさず、複数視点で重要な領域を優先する。
2. **多視点整合pruning**: 収束後半に寄与の低いGaussianを削り、巨大な点群を延々更新する時間を減らす。
3. **compact tile intersection**: Gaussianごとの無関係な描画tile候補を減らす。
4. **高被覆フレーム**: 243候補中180枚（約74%）を保持し、時間区間ごとの代表を必ず残す。以前の120/240より撮影済み視点を落としにくい。
5. **品質の数値検証**: 180枚はすべて学習し、完了後に固定間隔の参照viewでPSNR/SSIM/LPIPSを測る。未知視点の汎化値ではないが、被覆を削らず再構成忠実度を比較できる。
6. **再開可能な保存**: 15,000 iterationのPLY/チェックポイントと30,000 iterationの最終モデルをDriveへ直接保存する。
7. **T4 VRAM保護**: 入力画像はCPU側に置き、16GBのGPUメモリをGaussianとrasterizerへ優先配分する。画像内容や学習精度は変えない。

FastGS公式の屋内`room` base設定（densification間隔500、`highfeature_lr=0.02`、`grad_abs_thresh=0.0008`、compact-box倍率0.5）を使用し、実装commitも固定しています。公称の高速化率はColab T4の保証ではないため、30分は初回実測で判定する目標です。

## Mac実測: 解像度の影響

同一データセット(work/myvideo, COLMAP再構成済み)で2000ステップだけ計測:

| 条件 | 所要時間(2000step) | s/step |
|---|---|---|
| 長辺1600px・splats上限200万(standard既定) | 783.1秒 | 0.392 |
| 長辺1080px・splats上限200万 | 557.6秒 | 0.279 |

差分から、起動時の固定オーバーヘッドが約350秒（約6分）あると推定されます
（画像読み込み + wgpu/Metalのシェーダー オートチューニング）。これを差し引くと、
解像度による定常状態の高速化率はほぼ理論値通り**約2倍**(ピクセル面積比 (1600/1080)² ≈ 2.19 に近い)。

短い学習でもこの下限コストは残ります。

## 効くレバー

1. `--long-edge`: 1 stepの画素数に直接効く。1600→1080はMac実測でも大きく短縮。
2. `--max-splats`: Gaussian数が増えた学習後半に直接効く。旧Colab版は約9,300 stepで150万上限へ達し、残り約5,700 stepを巨大な点群で回していました。
3. `--steps`: ほぼ線形に効くが、反復だけ減らしてGaussian上限を高く残すより両方を揃えて下げる方が安全。
4. `--frames`: 1 stepの計算量は減らさないが、SfMの特徴抽出・照合・Mapperに効く。無作為に減らさずキーフレーム選別する。
5. SH degree: Colab版は3→2。強い鏡面反射の視点依存表現を少し簡略化する代わりに、各Gaussianの係数を減らす。

## 現在の推奨設定

```bash
python3 splat.py input/myvideo.mp4 --preset standard --view
```

Mac `standard`: 120枚・1280px・10,000 step・60万上限。Colabの速度優先は `balanced`: 120枚・1280px・8,000 step・60万上限・SH2。品質優先かつ30分目標は `fast_quality`: 180枚・1600px・30,000 iteration・SH3。

`balanced` のT4目標時間は20〜35分です。`fast_robust` は同一動画のT4初回実測で全工程29.1分（151/180枚登録、131,667 Gaussian）でした。速度目標は達成しましたが、広い室内では細部不足が目視確認されており、実効視点被覆とdensification判定は改善余地があります。

## 品質を戻す順序

軽量版で欠けが目立つ場合は、次の順で1段ずつ上げます。

1. キーフレーム 120→160（未再構成領域を補う）
2. Gaussian 60万→100万（細部を補う）
3. step 8,000→12,000（収束を進める）
4. 長辺1280→1600、SH2→3（最後に見た目の細部・反射を上げる）

一度に全部を旧設定へ戻すと、どの要素が品質に効いたか分からず、再び90分級へ戻ります。

## 検証すべき指標

- 総時間だけでなく、抽出・特徴抽出・照合・Mapper・学習を別々に記録する
- SfM登録枚数/入力枚数を旧99/180と比較する
- 最終Gaussian数、PLYサイズ、目視欠け、浮遊点、視点変更時の破綻を比較する
- 速くても登録率50%未満なら学習を開始しない
